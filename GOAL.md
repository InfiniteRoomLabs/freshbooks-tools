## Lessons from prior runs (read before starting)

Seeded from `hoyle-re` (the reference implementation of this loop). Append, never rewrite.

- **Verify the premise before implementing.** Two of three hoyle-re autonomous runs found the goal's own premise wrong. Here the premise is the spec's reading of the FreshBooks API (section 3) and the Postman inventory; the API's actual behaviour wins over the spec, and the spec gets a `STATE AS OF` callout in the same run.
- **Model tiers are pinned in agent definitions, not inherited.** Omitting `model:` on an `Agent` call uses whatever the agent file pins (several agent-ops agents pin haiku). Pass `model:` explicitly on every dispatch, and keep reviewers one tier above the implementer (sonnet -> opus, opus -> fable). Never use haiku for anything that could hit a permission prompt -- it has no auto mode and stalls the run.
- **Check the agent's `tools:` list before writing its prompt.** Most agent-ops review agents lack `Bash` or `SendMessage` and will appear to end silently. `general-purpose` (tools `*`) works for every lane.
- **Tell agents HOW to deliver.** A named background agent's final text does not reach the lead by itself. Instruct it to call `SendMessage` to **`team-lead`** (not `main`) with the full report in `message` (not `summary`), AND to write the same report to `docs/phases/<n>/reports/<lane>.md`.
- **Only the QA lane runs the gate.** Concurrent `mise run check` runs in one tree collide on build and coverage outputs. Code-review, simplification, and security lanes are read-only (`git`, `grep`, read).
- **A green HEAD says nothing about a dirty working tree.** Verify `git status --porcelain` is empty before reporting a gate result or claiming a fix landed.
- **The changelog guard is a Claude hook, not a git hook.** Commits on `main` are blocked unless `CHANGELOG.md` is staged. Write the changelog entry with the commit, not after. The version guard also requires `git add` and `git commit` as **separate Bash calls** (no `-a`/`-am`, no `&&` chaining).
- **Bash `cd` persists across tool calls.** Use absolute paths or `git -C <dir>` for worktree and module commands; never rely on the cwd a previous call left behind.
- **Public repo from commit 1.** Run `scripts/redaction-check.sh` before every commit once it exists; until then grep staged content for vault item names, internal IPs and hostnames, real account/business IDs, tokens, and personal names. Fixture IDs are synthetic.
- **(Phase 0) The lead's own commits need the redaction check too.** The work order `docs/phases/0/plan.md` carried the absolute repo path (the operator's home directory) and only the security lane caught it; it took a `git filter-repo --replace-text` pass on the branch before the first push. Write `<repo root>` in work orders, and run `scripts/redaction-check.sh` on every lead commit, not just implementer commits.
- **(Phase 0) Count the inventory yourself before trusting a number in the spec.** "130 requests" was 108 leaves + 22 subfolders counted as requests; reality is 213. A 5-line Python walk of the collection in stage 1 is cheaper than a wrong batch plan in Phase 2.
- **(Phase 0) Lanes catch different things; run all three even for a scaffold.** Code review found a data bug the golden test could not see (byte-stable is not well-formed); security found a `contents: write` inheritance into the reusable CI workflow and the path leak; simplification found the check-script step list written twice. None overlapped.
- **(Phase 0) Coverage gates need an honest shape, not a filter.** Excluding `main.go` by filename hid tested code and let an all-`main.go` module pass vacuously. The fix that held: `cmd/*/main.go` contains exactly one statement, everything else lives in a tested package, and an empty filtered profile is a hard fail.
- **(Phase 0) Pin third-party actions by SHA and check the major version.** The implementer wrote `jdx/mise-action@v2`; the current release was v4. Verify with `gh api repos/<owner>/<repo>/releases/latest` before pinning.
- **(Phase 0) Duplicate agent deliveries happen.** A lane may re-send its report when it sees a second prompt; treat the second delivery as a no-op rather than re-triaging.
- **(Phase 1) Attended consent steps: build everything first, then present one URL per click.** The probe program ran headless in the background with its authorize URL surfaced in chat; two clicks covered both endpoint sets. A background task waiting on a browser callback trips the harness's "appears to be waiting for interactive input" warning -- false alarm, do not kill it.
- **(Phase 1) The permission classifier can block `cp` from the session scratchpad into the repo.** Route the content through Read + Write instead of fighting it.
- **(Phase 1) Commit the read-only lanes' reports BEFORE dispatching QA, and tell QA its own uncommitted report is the one allowed dirty file** -- otherwise its clean-tree check false-fails on files the process itself created.
- **(Phase 1) Independent lanes converge on real blockers.** All three judging lanes found the same `Token.String` method-set leak with no shared context; the one-tier-up reviewer rule and lane independence both paid. Also: a lane can be wrong -- security claimed govulncheck never ran, QA refuted it from `scripts/check.sh`; triage catches lane-vs-lane conflicts.
- **(Phase 1) Give the implementer the triage as a numbered fix list with agreed actions (F1-F11) and the explicit non-applies.** The fix commit came back complete, on-message, and green on the first try; ambiguity in a fix order is where second fix commits come from.
- **(Phase 2) Never pipe the gate through `tail`/`head`.** `mise run check 2>&1 | tail` reports tail's exit code and once masked a red gate. Redirect to a log file and capture `$?` directly.
- **(Phase 2) Fixtures authored from the struct mask decode failures.** Every batch's QA blockers were latent decode failures on fields null or absent in the fixtures. The countermeasure that caught all of them: a QA probe decoding the repo's CAPTURED Postman response bodies through the read models (zero failures required, silent-drop counts reported). Make it a standing QA step; seed fixtures from captures with synthetic IDs, never from the struct.
- **(Phase 2) Parallel worktrees cannot inherit mid-phase conventions.** Batch a's gate created `pathSegment`/`listOpts`/`newPage`/`softDelete`; batches b/c/d, written concurrently, all lacked them and every later gate re-found the same classes. Expected cost of parallelism: prime later lanes with the earlier gates' bug classes (it worked -- they found them all), and budget one convergence pass per batch.
- **(Phase 2) Sequential merge + rebase-before-gate works.** ignore.list/CHANGELOG/spec conflicts were keep-both or drop-both resolutions; only the transport collision (two batches redesigning one file) needed lead judgment, and the next gate reviewed that merge explicitly.
- **(Phase 2) QA findings can be wrong too.** A QA blocker mandated a type change based on a value read through Python's `print()` (which strips quotes); the fix regressed decode and QA's own probe caught it on re-verify. Verify a finding's evidence shape with `repr`, and re-run the acceptance probe after every fix commit.
- **(Phase 2) The dirty-tree guard and the QA lane's uncommitted report fight.** QA must run the gate before writing its report (or stash it); teach `scripts/check.sh` to ignore `docs/phases/*/reports/` eventually (backlog).
- **(Phase 2) A lane may deliver its report via SendMessage but never write the file**, even when told twice. Check the file exists before the reports commit; transcribe from the message when missing.
- **(Phase 2) Agent hygiene:** TaskStop lane agents right after triage, implementer+QA after the merge (now a CLAUDE.md convention). Duplicate dispatch deliveries still happen; agents handled them as no-ops when the work order said to.
- **(Phase 3) Probe the SDK against every lib type in stage 1, not in the implementer's lap.** A 40-line reflection probe found go-sdk's schema inference failing on 54 of 169 lib types before any code was written; the verified three-override recipe went into the work order and the implementer never hit it. Cheapest premise check of the project so far.
- **(Phase 3) Framework code that runs before your handler is inside your trust boundary.** The module's error mapping was careful, but go-sdk validates arguments first and quotes the offending value; the written "never echo card input" constraint was false on that path. Security caught it by reading the SDK, not the module. Write constraint tests with schema-INVALID input as well as the happy path.
- **(Phase 3) A round-trip test that asserts only "no error" is mutation-blind.** 168 rows passed while swapping `bills_delete`/`bills_archive` bodies or crossing ID families would also have passed. Put the exact assertions (recorded method, path with scope id, body for writes, query for options) in the work order's acceptance criteria and have code review check the tests against that sentence.
- **(Phase 3) Capture the tool manifest before and after a refactor commit.** `freshbooks-mcp tools > before.json` / `diff` after the fix commit is a zero-cost proof that fifteen fixes changed no name, description, annotation, or schema. Any phase with a generated surface (Phase 4's `docs/cli.md`) should do the same.
- **(Phase 3) Inspect real wire output, not just decode success.** Four lanes missed that `Page[T]` and `User` have no `json` tags because nothing looked at a marshaled result; QA's own probe of one result per family found 23 tools emitting Go-cased keys. Make "print one actual result per family" a standing QA step alongside the captured-response decode probe.
- **(Phase 3) `mise exec -- go`, never bare `go`, for probes.** The machine's bare `go` was version-skewed against mise's pinned toolchain mid-run (`compile: version mismatch`); only `mise exec` matched what the gate runs.
