## Stage-1 decisions you inherit (do not re-open; report if reality disagrees)

- **D1 -- registry, not hand-written commands.** `cli/internal/cmd/registry.go` holds `[]Command` specs (group, verb, service, method, inventory keys, annotation class, scope family, positional args, flag set, and a `Run func(ctx, *freshbooks.Client, *Invocation) (any, error)` closure). `BuildTree(root, deps)` generates the cobra tree from it. Per-resource `commands_<resource>.go` files mirror the lib layout.
- **D2 -- `--all` covers the iterators.** A list command with `--all` drives the service's `All` iterator and collects into a slice (with `--page`/`--per-page` rejected alongside it, exit 2). No `*_all` commands.
- **D3 -- `api` needs no lib change.** `freshbooks api <METHOD> <path> [-f body|-] [-q k=v]...` calls `(*Client).Do` with `-q` pairs appended to the path's query and `out` as `*json.RawMessage`; output goes through the normal formatter.
- **D4 -- `--dry-run` is an `http.RoundTripper`.** The lib owns request building, so dry-run installs a transport (via `WithHTTPClient`) that prints `METHOD URL` and the body (never the `Authorization` header) to stdout and returns a sentinel error the CLI maps to exit 0 with nothing sent. A dry-run needs a token source but must never refresh: use a static placeholder source in dry-run mode.
- **D5 -- credentials are one lib `FileStore` per context** at `$XDG_CONFIG_HOME/freshbooks/credentials/<context>.json` (0600 via the lib), and `config.yaml` beside it holds only `current-context` and `contexts.<name>.{account, business, business_uuid}` -- no secrets ever. `FRESHBOOKS_CLIENT_ID`/`FRESHBOOKS_CLIENT_SECRET` come from env or `--client-id/--client-secret` flags on `auth login|token|logout` only and are never written anywhere.
- **D6 -- exit codes:** 0 ok; 1 API or runtime error; 2 usage (cobra parse errors, bad JSON body, missing scope, `--all` with `--page`); 3 auth (no credentials for the context, or the API answered 401); 4 not found (API 404). Under `-o json`, errors are one JSON object on stderr `{"error": {"status", "code", "message", "field", "family", "exit"}}`; otherwise one human line.
- **D7 -- output:** `-o json|yaml|table|name`; default `table` when stdout is a TTY (`golang.org/x/term`), `json` otherwise; `--no-headers`; `-q` suppresses non-result chatter. `table` is deliberately simple: marshal the result to JSON, one row per element of a `Page[T].items` / slice / single object, columns = the top-level scalar keys in JSON order, values stringified, nested objects/arrays elided as `<n keys>`/`<n items>`; `name` prints the `id` (falling back to `name`, `uuid`) of each row, one per line.
- **D8 -- lib fold (its own commit, `feat(freshbooks): add json tags to Page, User, and Membership`)**: `freshbooks/page.go` `Page[T]` gets `json:"items"`, `"page"`, `"pages"`, `"per_page"`, `"total"`; `freshbooks/identity.go` `User` gets `"id"`, `"email"`, `"first_name"`, `"last_name"`, `"memberships"` and `Membership` gets `"account_id"`, `"business_id"`, `"business_uuid"`, `"name"`, `"role"`. No decode path changes (both are built from separate wire structs). Add a `freshbooks/CHANGELOG.md` `[Unreleased]` line. Then add one sentence to `docs/mcp.md` describing the list envelope (`{"items": [...], "page", "pages", "per_page", "total"}`). This is the ONLY lib change permitted; anything else, stop and report.
- **D9 -- MCP fold (its own commit, `fix(mcp): harden the gate's advisory findings`)**: `strings.EqualFold` on the `Bearer` scheme in `mcp/internal/server/server.go` (RFC 7235 case-insensitive scheme) with a test; in `mcp/internal/tools/redaction_test.go` give `payment_options_save_credit_card`'s invalid row a sensitive value to look for, assert `!IsError` on the well-typed rows, and skip the empty-log containment check when the log buffer is empty (comment why); in `roundtrip_test.go` assert `page=7`/`per_page=13` as `key=value`. ## Deliverables

### `cli/internal/cmd`

- `registry.go`: the `Command` spec type, `All []Command`, `BuildTree`. Generic invocation plumbing: scope resolution (`--account`/`--business`/`--business-uuid` flag > `FRESHBOOKS_ACCOUNT_ID`/`FRESHBOOKS_BUSINESS_ID`/`FRESHBOOKS_BUSINESS_UUID` env > current context in `config.yaml`; missing -> exit 2 naming the flag), positional `<id>` parsing (int64 or string per the lib signature), `-f file|-` JSON body decoded into the lib request struct (unknown fields rejected with `DisallowUnknownFields`; bad JSON -> exit 2), list flags (`--page`, `--per-page`, `--search k=v` repeatable, `--include` repeatable where the lib option has it, `--sort field[:asc|desc]` where the lib `List` takes `...RequestOption`, `--all` per D2), `--yes` required for every `D`-class command when stdin is a TTY (otherwise the command refuses with exit 2 and a one-line hint), binary results (`invoices pdf`, `reports download-invoice-details-csv`) written to `-o <file>` (or stdout when `-`), uploads from `--file <path>` (the CLI opens the path; the lib bounds the size).
- `commands_<resource>.go` x ~33 with the per-command closures and stacked `// inventory:` comments above each resource's slice (keys live in the spec data too, as in the MCP).
- Global flags on root: `-o/--output`, `--account`, `--business`, `--business-uuid`, `--context`, `--config`, `--no-headers`, `-q/--quiet`, `--dry-run`, `--yes`, `--timeout` (default 30s), `--log-level`, `--base-url` (hidden, tests and sandboxes). Every global flag has a `FRESHBOOKS_*` env twin (`FRESHBOOKS_OUTPUT`, `FRESHBOOKS_CONTEXT`, `FRESHBOOKS_CONFIG`, `FRESHBOOKS_TIMEOUT`, `FRESHBOOKS_LOG_LEVEL`, `FRESHBOOKS_BASE_URL`); flag > env > config file > default; an empty env var is unset.
- Non-registry commands: `auth login|status|logout|token`, `config view|contexts|use-context|set-context`, `api`, `completion` (cobra's), `version`, and a hidden `docs <dir|file>` used by `scripts/docs.sh`.
- `Run(args, stdout, stderr, version) int` stays the seam; it maps errors to D6 exit codes. `main.go` stays one statement.

### `cli/internal/auth`

- `Login(ctx, opts)`: builds `auth.Config{ClientID, ClientSecret, RedirectURL: "https://localhost:<port>/callback", Scopes}` (default port 8765; default scopes the full `user:*:read`/`write` set from https://www.freshbooks.com/api/scopes -- read the page, list them in code with the docs link), generates `state` (crypto/rand, 32 bytes, base64url), gets the URL + verifier from `Config.AuthCodeURL`, starts a loopback listener on `127.0.0.1:<port>` with an ephemeral self-signed ECDSA P-256 cert (SANs `localhost`, `127.0.0.1`; 1h validity; generated in-process with `crypto/x509`, never written to disk) serving `/callback` exactly once, validates `state` (mismatch -> error, exit 1, listener closes), exchanges the code, and saves through the context's `FileStore`. Opens the browser with a fixed program per OS (`xdg-open`, `open`, `rundll32 url.dll,FileProtocolHandler`) passing the URL as an argument (no shell). A 5-minute timeout closes the listener. The success page tells the user the browser warning about the self-signed cert is expected and they can close the tab.
- `--no-browser`: prints the URL, reads one line from stdin -- the full redirected URL or a bare code -- validates `state` when a URL is given, exchanges. No listener.
- `Status`: context, credentials path, `Valid` (via `Token.Valid` with the lib's skew), expiry timestamp, scopes; never the token. `Token [--refresh]`: prints the access token to stdout (this is the one place a token is printed; document it), `--refresh` forces `Config.Refresh` + store `Save` first. `Logout`: best-effort `Config.Revoke` on the refresh token, then removes the credentials file; missing file is not an error.
- Every registry command builds its client with `auth.NewTokenSource(cfg, store)` so rotation writes back through the lib; no credentials -> exit 3 with `run 'freshbooks auth login'`.

### `cli/internal/config`

- `Load(path)` / `Save`: `config.yaml` via `gopkg.in/yaml.v3` at `$XDG_CONFIG_HOME/freshbooks/config.yaml` (falls back to `~/.config`), `--config` overrides; created 0600 in a 0700 dir, written atomically (temp + rename); a missing file is an empty config. `Context{Account, Business, BusinessUUID}`; `CurrentContext`; `Resolve(flags, env) Scope`. `config view` prints the file (yaml or `-o`); `contexts` lists; `use-context` switches; `set-context <name> --account --business --business-uuid` creates/updates.

- **Round trip per command** with request recording: for each registry entry, run the cobra tree in-process (`Run(args, ...)` with `--base-url` pointed at an `httptest.Server` that records method/path/query/body and serves a decodable fixture per family -- reuse `freshbooks/testdata` fixtures), assert exit 0, the recorded method matches the class (RO -> GET), the scope id from the context appears in the path, write commands carry a body value from the synthesized input, `--page 7 --per-page 13 --search k=v` land in the query as `page=7`/`per_page=13`, `--all` walks two pages, `-o json` output parses and (for one command per family) round-trips through the lib type. - **Exit codes**: one test per code (0, 1 on 500, 2 on bad JSON and on missing scope and on `--all --page`, 3 on no credentials and on 401, 4 on 404), JSON error object on stderr under `-o json`.
- **Login flow** end to end against an httptest OAuth server (authorize endpoint that redirects to the loopback with `code`+`state`; token endpoint asserting `code_verifier`, `client_id`, `client_secret`, `redirect_uri`): happy path saves a 0600 file; wrong `state` rejected and nothing saved; timeout path; `--no-browser` with a pasted URL and with a bare code; `auth token --refresh` rotates and persists the new refresh token before printing; `auth logout` revokes and removes; `auth status` never prints the token.
- **Redaction**: capture stdout/stderr/log for `config view`, `auth status`, `--dry-run`, an API error, a 401 -- assert the access token, refresh token, and client secret from the fixtures never appear.
- **Dry run**: prints `METHOD URL` and body, no upstream request recorded, exit 0, no `Authorization` header in the output.
- **Output**: table/json/yaml/name each demonstrated for a page, an object, a slice; TTY vs non-TTY default (inject the TTY check).
- **Config**: precedence flag > env > file > default; empty env unset; atomic write; missing file OK; `use-context` unknown name -> exit 2.

## Gotchas

- `go.work` is in force; run `go` from inside `cli/` or with `-C cli`; `GOFLAGS=-mod=mod` is rejected.
- Two ID families plus `BusinessUUID`; the scope family per command comes from the lib signature, never converted. `Staff`, `Services`, `Systems`, `Reports.TimeEntryDetails` mix families within one service -- mirror `docs/phases/3/tools.md` and the MCP registry.

- Stdout carries results only; everything else goes to stderr. `-q` silences stderr chatter, not errors.
- The lib's `Token.Valid(now, skew)` and `created_at + expires_in` expiry: use the lib, do not re-derive.
- Docs are ASCII-only, no hard wraps; fixture IDs, tokens, and names are synthetic; never a real account id.
