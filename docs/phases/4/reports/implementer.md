## What shipped

- **`cli/internal/output`** (`output.go`): `Write(w, value, Options{Format, NoHeaders})` for `json|yaml|table|name`. Table columns come from a streaming-decoder key order (map iteration order is not JSON order), yaml numbers stay unquoted via a `json.Number`-preserving decode, table/name share one row-splitting rule (`Page[T]`'s `{"items":[...]}` shape, a bare array, or a single object).
- **`cli/internal/config`** (`config.go`): `config.yaml` (`current-context`, `contexts.<name>.{account,business,business_uuid}`), atomic 0600 writes in a 0700 dir, `Resolve(flag, env, file, def)` implementing the flag > env > file > default chain every scope field and global flag uses.
- **`cli/internal/auth`** (`login.go`, `status.go`, `paths.go`, `scopes.go`): the loopback PKCE flow over an ephemeral in-process self-signed ECDSA P-256 certificate (never written to disk), state validation on the single `/callback` request, `--no-browser` paste fallback (full URL or bare code), `Status/Logout/Token` wrapping the lib's `FileStore`/`TokenSource`. `DefaultScopes` is the full `user:<object>:{read,write}` set for the 22 objects at https://www.freshbooks.com/api/scopes. Credentials: one `FileStore` JSON file per context at `$XDG_CONFIG_HOME/freshbooks/credentials/<context>.json`.
- **`cli/internal/cmd`**: the data-driven registry — `registry.go` (`Command`, `Invocation`, `BuildTree`, mirroring `mcp/internal/tools/registry.go`'s `Spec`/`Call`/`Register` shape), `invocation.go`, `state.go` (scope/output/client/dry-run plumbing), `errors.go` (D6 exit-code mapping), `term.go`. 33 `commands_<resource>.go` files declare the 168 registry rows. Non-registry commands: `api_cmd.go` (D3 escape hatch), `auth_cmd.go`, `config_cmd.go`, `docs_cmd.go` + `docsgen.go` (hidden `docs` command, `cobra/doc`-generates `docs/cli.md`). `root.go` carries every global flag and the top-level exit-code/JSON-error-object mapping.
- **`docs/cli.md`**: generated by `scripts/docs.sh` (`mise run docs`) via the CLI's own hidden `docs` command; hand-written header (install, first login, contexts, output formats, exit codes, automation notes, the `api` escape hatch, security notes) followed by one `cobra/doc` section per command, depth-first, sorted. Verified idempotent (byte-identical on a second run) and guarded by a standing drift test.
- **D8 fold** (`freshbooks/page.go`, `freshbooks/identity.go`): `json` tags on `Page[T]`, `User`, `Membership` matching their wire shape — the only lib change this phase touches.
- **D9 fold** (`mcp/internal/server/server.go`, three `mcp/internal/tools/*_test.go` files): case-insensitive `Bearer` scheme match (RFC 7235) plus three test-hardening fixes from the Phase 3 gate's advisory findings. `Staff` (`List` is business-scoped, `Get/Update/Delete` are account-scoped), `Services` (`Get/List` business-scoped, `Create/GetBillableItem` account-scoped), `Systems.Get` (needs **both** account and business at once — added `ScopeAccountAndBusiness` rather than treating one as a positional id), `Reports.TimeEntryDetails` (business-scoped, unlike every other `Reports.*` method).

### Scope reductions made deliberately, not discovered as bugs

- **`--sort` was not implemented.** The work order's own deliverables text hedges it as `where the lib List takes ...RequestOption`, and `docs/phases/4/commands.md` — the definitive authority per the plan — never names `--sort` in any of the 168 rows' flags column. Given the scale of the rest of the surface, this was cut rather than guessed at.
- **`--include` was only wired for `List` commands whose `*ListOptions` struct has a real `Include []string` field** (`clients list`, `estimates list`) — not for `Invoices.Create/Update` or `InvoiceProfiles.Create`, which the "gotchas" note says also accept it via variadic `RequestOption`. `commands.md`'s flags column never calls this out on those rows either (`B` only), so it was left out to keep the write commands' shape simple (JSON body only).
- **The 14 report commands (`reports *`) do not get per-report bespoke flags.** `commands.md` says "report opts as flags," but each of the 13 filter-struct reports has its own distinct field set (date ranges, currency, grouping) — 13 separate flag-to-field mappings was out of scope for one pass. Instead every report command takes its filter options the same way a write command takes a body: an *optional* `-f/--file` JSON document decoded into the report's `*XxxOptions` struct (`Invocation.DecodeBodyOptional`, a new method alongside `DecodeBody`). The full filtering capability is still reachable, just through one flag instead of many.

### A design collision the plan didn't anticipate: `-q`

The plan's own command surface (`freshbooks api ... [-q k=v]`) and the global persistent `-q/--quiet` flag both want the shorthand `q`. `pflag`'s `AddFlagSet` only skips a flag that already exists **by name**; a same-shorthand, different-name collision panics at cobra's flag-merge time (`Command.Find`, which runs on every invocation, not just `api`). This is why the Binary commands' local `-o/--output` shadowing the global `-o/--output` works fine (same name) while `api`'s local `-q/--query` shadowing the global `-q/--quiet` does not (different name, same shorthand). Resolved by dropping the shorthand from `api`'s `--query` flag; it is long-form only (`docs/cli.md` reflects this).

### `Run`'s signature grew a `stdin` parameter

The work order says `Run(args, stdout, stderr, version) int stays the seam`, but `-f -` (JSON body from stdin) and `auth login --no-browser`'s paste prompt both need a stdin source, and cobra's own `InOrStdin()` defaults to the real `os.Stdin` unless a caller sets it — which would make it untestable without a real terminal. Extended to `Run(args, stdin, stdout, stderr, version) int`; `main.go` passes `os.Stdin`; `root_test.go`'s two existing call sites were updated. Also updated `root_test.go`'s "unknown subcommand" expectation from exit 1 to exit 2 to match D6 (a cobra-level parse/dispatch failure is a usage problem by construction — see `errors.go`'s `exitCodeFor` doc comment for why every untyped error reaching it can only have come from cobra itself).

### Two real bugs the round-trip test caught (both fixed in the test-suite commit, not left for the gate)

1. `EstimatesService.Send` validates client-side that it has at least one recipient before building any request, so the generic `{}` probe body used for every other write command fails before ever reaching the fixture server. `estimates send` gets a real recipient in its round-trip probe body instead of the shared empty one.
2. `config.File`/`config.Context` had no `json` tags, so `config view -o json` printed Go-cased `CurrentContext`/`Account`/... instead of the documented `current-context`/`account`/... keys every other command's JSON output uses. Fixed alongside its test.
