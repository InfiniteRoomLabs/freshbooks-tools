Dispatch: `Agent(subagent_type: "general-purpose", model: "sonnet", name: "phase-9-impl")`. Unattended. **No network writes by the implementer**: no `git push`, no tag pushes, no `gh release`/`gh api` mutations; every network-touching path is exercised only through `--dry-run` or the fake `gh`/`git` shims in the self-test.

## The inventory to automate (what the lead did by hand for v0.1.0, v0.2.0/0.1.1, v0.3.0/0.1.2)

Preconditions: `main` green on GitHub (`gh run list --workflow CI --branch main --limit 1` conclusion `success` for HEAD), `git status --porcelain` empty, `gh auth status` shows `repo` + `workflow`, on branch `main`, `mise install` current, the tag ruleset for `refs/tags/{freshbooks,mcp,cli}/v*` (warn only, print the `gh api` call).

Library release `freshbooks/vX.Y.Z`: (1) bump kind from `freshbooks/CHANGELOG.md` `[Unreleased]`: `**Breaking:**` or `### Changed` -> minor while `0.x`, `### Added` -> minor, only `### Fixed` -> patch; (2) rename `## [Unreleased]` to `## [X.Y.Z] - <date>` with a fresh empty `## [Unreleased]` above; (3) root `CHANGELOG.md` `[Unreleased]` `### Added` line; (4) `git add` then `git commit -m "release(freshbooks): vX.Y.Z"` (separate calls: the agent-ops guards inspect the index), `git push origin main`, watch the CI run for that sha to `success`; (5) `git tag -a freshbooks/vX.Y.Z -m "freshbooks vX.Y.Z"`, `git push origin freshbooks/vX.Y.Z`; (6) `gh run list --workflow Release --branch freshbooks/vX.Y.Z --limit 1` then `gh run watch --exit-status`; (7) `gh release view freshbooks/vX.Y.Z`: not draft, `name` equals the tag, 0 assets; (8) proxy pickup: `cd /tmp && GOFLAGS=-mod=mod go list -m github.com/InfiniteRoomLabs/freshbooks-tools/freshbooks@vX.Y.Z`, up to 6 tries 20s apart, using the toolchain pinned in `mise.toml` by absolute path (`mise where go`), because `mise exec` outside the repo resolves the global pin.

Bump commit: (9) in `mcp/` and `cli/`: `go get github.com/InfiniteRoomLabs/freshbooks-tools/freshbooks@vX.Y.Z` (same retry) and `go mod tidy`; (10) each module's `[Unreleased]` gets a `### Changed` line "Requires `freshbooks` vX.Y.Z" (keep whatever is already there) and is renamed to its own `## [A.B.C] - <date>`; root line; (11) full `mise run check` (the dirty-tree banner on the staged bump is the only expected failure: run the gate before staging, or accept exit 1 only when every step before the banner passed -- prefer running `mise run check` with the changes committed on a temporary basis is NOT allowed; instead run the per-module steps `fmt-check vet lint test cover` via `scripts/check.sh` and skip the banner), commit `release(mcp,cli): require freshbooks vX.Y.Z and cut A.B.C`, push, CI watch.

Binary release `mcp/vA.B.C` and `cli/vA.B.C` (parallel allowed): (12) annotated tag, push; (13) Release watch filtered `--branch <tag>`; (14) `gh release view <tag>`: not draft, named, 13 assets; (15) download `<binary>_A.B.C_linux_amd64.tar.gz` + `checksums.txt` into a temp dir, `sha256sum -c checksums.txt --ignore-missing`, extract, run `version`: the MCP binary prints `freshbooks-mcp A.B.C`, the CLI prints `A.B.C` (no prefix); (16) `GOBIN=<tmp> go install <module>/cmd/<binary>@vA.B.C` outside the workspace (pinned toolchain path, `-u GOWORK`, `GOFLAGS=-mod=mod`), `version` prints `freshbooks-mcp vA.B.C` / `vA.B.C`; for the CLI `go version -m` must show no `md2man` or `blackfriday`; (17) dogfood: install both binaries into `$(mise env | grep PNPM_HOME >/dev/null; echo ~/.local/bin)` -- use `~/.local/bin` -- so the operator's local install is the released build.

Afterwards: (18) `README.md` Status column rows to the newest tag per module; `docs/progress.md` ledger row; commit `docs: ship vX.Y.Z`, push, CI watch.

## Decisions

- **D1 -- `scripts/release.sh`**, `usage` shebang, subcommands: `preflight`, `cut <module> <version>`, `bump <lib-version> [--binary-version A.B.C]`, `verify <tag>`, `docs`, `all <lib-version> [--binary-version A.B.C]`. Flags: `--dry-run` (print every git/gh/go command that would run, perform no push/tag/release, still perform read-only checks), `--yes` (skip the TTY confirmation before the first push), `--version auto` accepted by `cut` and `all` (derive the bump per step 1, print the proposal, require `--yes` or a TTY `y`). `mise.toml` gets `[tasks.release]` -> `scripts/release.sh "$@"`.
- **D2 -- output contract.** One line per step: `release: OK <step>` or `release: FAIL <step> -- expected <x>, observed <y>` then exit 1; `release: SKIP <step> -- <reason>` for resume. Nothing else on stdout; command echo under `--dry-run` goes to stdout prefixed `dry-run:`. Never print a token: the script must not read `FRESHBOOKS_*` or `GITHUB_TOKEN`; it relies on `gh`'s own auth.
- **D3 -- resume.** Each mutating step checks its postcondition first: changelog already cut (`## [X.Y.Z]` present) -> SKIP; release commit already on `main` (subject match in `git log -1`) -> SKIP; tag on the remote (`git ls-remote --tags origin <tag>`) -> SKIP the tag push; release published (`gh release view`) -> SKIP; verification never skips.
- **D4 -- CI/Release watching.** Find the run by sha (`gh run list --workflow CI --branch main --json databaseId,headSha`) or by tag (`--branch <tag>`), poll `gh run view --json status,conclusion` every 30s with a 20-minute cap (`--timeout <seconds>` overridable); a cap hit is `FAIL`.
- **D5 -- `docs` subcommand** rewrites the three README Status cells from `git tag --list '<module>/v*' | sort -V | tail -1` and appends nothing else; `scripts/docs.sh` calls it after `docs/cli.md` generation so `mise run docs` and the drift test cover the Status column (add a test in `cli/internal/docsgen` or a shell check in `scripts/check.sh` that `README.md` is unchanged after `release docs`).
- **D6 -- self-test** `scripts/release-selftest.sh` (`usage` shebang, wired into `scripts/check.sh` beside `redaction-selftest` and as `mise run release-selftest`): builds a scratch repo under `mktemp -d` with the three module layouts, changelogs, and a fake `origin` (a bare repo), puts a fake `gh` and fake `go` on `PATH` (bash scripts that log their argv to a file and answer the JSON the real ones would: run lists with `success`, release views with 13 or 0 assets, `go list -m` success, `go install` writing a stub binary that prints the expected version string, `sha256sum` real), then asserts: `all 0.9.0 --dry-run` prints the full plan with zero pushes recorded by the fake origin; `all 0.9.0 --yes` against the fakes completes with every step `OK` and the fake origin holds the three tags and the commits; re-running it prints `SKIP` for every mutating step and re-runs `verify`; a fake `gh` answering `failure` for the Release run makes `cut` FAIL before any tag push of the next module; `verify` FAILs when the stub binary prints the wrong version string or the checksum file is altered; `--version auto` proposes patch for a Fixed-only changelog and minor for Added; `preflight` FAILs on a dirty tree and on a non-main branch. Nothing in the self-test reaches the network (`GH_HOST=localhost` and the fake `gh` never calls out; `git push` targets the bare repo only).
- **D7 -- docs.** `docs/building.md` release-flow section rewritten around `mise run release`; `docs/progress.md`'s "v0.1.0 tag step" and tag-flow prose replaced by one pointer to the command; `CHANGELOG.md` root `[Unreleased]` `### Added` line; no module changelog changes (nothing ships in a module).
- **D8 -- guards.** The script never uses `--force`, never deletes a tag, never edits branch protection or rulesets (`preflight` only prints the `gh api` call), and refuses to run when `git rev-parse --abbrev-ref HEAD` is not `main` (except `verify`, `docs`, and `--dry-run`).

## Rules

`usage lint` clean on both scripts; shell is bash with `set -euo pipefail`; no new dependencies (`gh`, `git`, `go` via the pinned path, `sha256sum`, `tar`, `jq` if already on the machine -- prefer `gh --jq`). Stage and commit in separate Bash calls; `scripts/redaction-check.sh` before every commit; conventional commits (`feat(scripts): ...`, `chore(mise): ...`, `docs: ...`); checkpoint commits per decision; `mise run check` green on a clean tree at the end; the self-test must pass inside the gate. No push, merge, or tags by you. Context budget: never cat large files; gate output to a log, read the tail.
